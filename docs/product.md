# 项目约定

本文件定义跨模块的使用预期。具体实现以代码为准，发行内容的维护规则见 [运行时维护指南](runtime-maintenance.md)。

## 产品定位

Wingmate 是面向个人使用的 DeepSeek Harness（DSH）发行版。它负责运行时分发和后台管理，并计划围绕同一后台提供多种接入方式。当前 Agent 业务由 DSH 提供，优先复用上游能力，按实际使用需求补充自有界面并集成社区和自用插件。

## 跨平台设计

通用功能采用跨平台设计，优先使用跨平台 API。需要调用系统专属能力时，将平台差异留在对应的适配层，共用业务规则。运行验证范围见[验证约定](../scripts/README.md#验证边界)。

## 需要保持的使用体验

- 桌面端以单个可执行文件交付应用及所选 DSH 运行内容。它可以声明系统前提，运行时应独立于开发仓库、构建缓存和开发目录链接。
- 发行入口不依赖 GUI；无 GUI 主机可通过 CLI 准备并运行后台。资源释放和版本协调归发行引导，客户端共用独立管理服务。
- 后台独立于窗口存活。关闭窗口不等于停止任务，再次打开应发现并连接已有后台；多个桌面实例可以共享同一个后台。
- 停止和重启是明确的管理操作。打开窗口、暂时失去连接或发现版本不同，不应擅自替换正在工作的后台。
- 精简服务于分发与使用体验，保留已选择的功能和插件兼容性，不以无记录的功能删除换取体积下降。

## 数据归属

发行版的 DSH 会话、凭据与设置沿用官方默认位置，不要求便携化或随可执行文件搬迁。Wingmate 的管理数据与可重新释放的运行内容独立存放，不能把它们与 DSH 用户数据一起清理。具体位置与管理边界见 [服务模块](../crates/wingmate-service/README.md)。

## 当前阶段的选择

| 选择 | 当前范围及取舍 |
| --- | --- |
| 无 GUI 的统一入口与可选桌面 | CLI 可独立准备和启动；桌面采用 Tauri，自有首页承担启动与恢复，聊天和 Agent 交互复用官方 Web |
| 使用系统 Node | 减少当前分发内容；内嵌 Node 是以后可以重新选择的方案 |
| 独立常驻管理服务 | 管理服务使用已安装的业务运行内容，业务停止后仍可再次启动。当前管理连接限本机，不作为远程访问方案 |
| 固定 npm 发布版本 | 构建使用明确版本及锁文件，当前不从上游源码编译 DSH |
| 按运行组件复用安装目录 | 同一 DSH 版本可以随包更新插件，切换时机见[运行时维护指南](runtime-maintenance.md#释放与复用) |
| Windows、macOS、Linux 桌面发行 | 按目标平台和架构分别构建发行包。具体组合取决于 Tauri、Node 和 DSH 原生依赖的可用性及运行验收 |

以上是当前交付范围，不是永久禁止变更的限制。改变选择时，应同步调整其使用前提和受影响模块的约定。

## 未来方向，尚未交付

多内核、远程接入、TUI 和 Android 的目标与实施顺序已整理到[临时架构与实施方案](../ARCHITECTURE_PLAN.md)。方案中独立管理服务与无 GUI 引导的落地边界见上表；其余目标尚未交付，实施后同步更新本文和对应模块文档。

更多按实际需求补充的自有前端、预装插件和自动选择最新发布 tag 仍属于后续方向，不自动纳入上述阶段任务。
