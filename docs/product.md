# 项目约定

本文件定义跨模块的使用预期。具体实现以代码为准，发行内容的维护规则见 [运行时维护指南](runtime-maintenance.md)。

## 产品定位

Wingmate 是面向个人使用的 DeepSeek Harness（DSH）发行版。它负责运行时分发和后台管理，并计划围绕同一后台提供多种接入方式。Agent 业务由 DSH 提供，优先复用上游能力，按实际使用需求补充自有界面并集成社区和自用插件。

## 需要保持的使用体验

- Windows 桌面端以单个可执行文件交付应用及所选 DSH 运行内容。它可以声明系统前提，运行时应独立于开发仓库、构建缓存和开发目录链接。
- 后台独立于窗口存活。关闭窗口不等于停止任务，再次打开应发现并连接已有后台；多个桌面实例可以共享同一个后台。
- 停止和重启是明确的管理操作。打开窗口、暂时失去连接或发现版本不同，不应擅自替换正在工作的后台。
- 精简服务于分发与使用体验，保留已选择的功能和插件兼容性，不以无记录的功能删除换取体积下降。

## 数据归属

发行版的 DSH 会话、凭据与设置沿用官方默认位置，不要求便携化或随 EXE 搬迁。Wingmate 的管理数据与可重新释放的运行内容独立存放，不能把它们与 DSH 用户数据一起清理。具体位置与管理边界见 [服务模块](../crates/wingmate-service/README.md)。

## 当前阶段的选择

| 选择 | 当前范围及取舍 |
| --- | --- |
| Tauri 桌面作为首个入口 | 自有首页承担启动与恢复，后台在线时从官方 Web 的设置管理后台。聊天和 Agent 交互复用官方 Web |
| 使用系统 Node | 减少当前分发内容；内嵌 Node 是以后可以重新选择的方案 |
| 本机常驻后台 | 当前连接范围是本机，不把本机发现与身份机制视为远程访问方案 |
| 固定 npm 发布版本 | 构建使用明确版本及锁文件，当前不从上游源码编译 DSH |
| 按运行包内容复用释放目录 | 同一 DSH 版本可以随包更新插件，切换时机见[运行时维护指南](runtime-maintenance.md#释放与复用) |
| Windows x64 优先 | 其他平台及架构需要独立验证，不能从本机通过推导为已支持 |

以上是当前交付范围，不是永久禁止变更的限制。改变选择时，应同步调整其使用前提和受影响模块的约定。

## 未来方向，尚未交付

计划支持 TUI、手机等移动端，以及从其他设备远程连接 Wingmate 后台。更多自有前端、更多预装插件和自动选择最新发布 tag 也属于后续方向。
