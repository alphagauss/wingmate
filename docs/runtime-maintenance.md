# 运行时维护指南

用于调整 DSH 版本、发行依赖、裁剪与压缩规则，以及集成社区或自用插件。这里保存选择依据和维护责任；脚本表达具体步骤，配置和锁文件保存精确版本。

## 来源与版本

当前从官方 npm 发布包获取 DSH，不从参考仓库复制编译产物。发行依赖声明以 [runtime/package.json](../runtime/package.json) 为准，依赖解析结果以其 [锁文件](../runtime/package-lock.json) 为准。

准备 DSH 运行包时默认通过 `https://registry.npmmirror.com/` 获取 npm 发布包，并按锁文件校验完整性。需要切回官方源时，在构建环境中设置 `npm_config_registry=https://registry.npmjs.org/`。已有运行包命中构建缓存时会直接复用。安装阶段会显示所选源，并在交互终端单行更新 npm 下载请求和缓存检查的次数，重定向输出时定期打印摘要。设置 `npm_config_loglevel=http` 可查看 npm 的逐请求日志。

一次发行需要能对应到明确的上游版本与依赖内容。以后即使支持“拉取最新 tag”，也应先选定并记录具体版本，再准备发行包；不把漂移的 `latest` 当作已确定版本，也不在用户每次启动时重新选择上游。

改用源码构建或社区 fork 时，记录来源 URL、tag 对应的提交及必要补丁。正式发行不能只依赖被忽略的上游工作副本。来源改变不自动意味着接受该来源新增的默认功能或行为。

## 打包范围与所有权

应用携带所选 DSH 及其运行依赖，系统前提见 [项目入口](../README.md#使用)。当前 Node 由系统提供，Zstd 解压能力随应用交付。用户凭据、会话、个人设置、开发缓存不属于预装运行内容。

新增组件需要明确它属于“随包提供”“使用系统安装”还是“用户按需安装/下载”，以及是否增加了使用前提。组件名称和版本放在实际依赖声明中，文档记录为什么加入，不维护第二份版本清单。

生成内容统一放在 `work`：开发依赖缓存位于 `work/dev/dependencies/<依赖指纹>`，可运行目录位于 `work/dev/runtimes/<内容指纹>`，`current` 文件指向最近准备的目录；发行归档位于 `work/build/runtime`，npm 下载缓存位于 `work/cache/npm`。Rust 仍使用原 `target`。`runtime` 只保存受版本管理的声明、锁文件、补丁与控制代码。旧 `runtime/.cache`、`runtime/out` 在首次准备时迁移；旧开发安装树在新开发后台成功启动后回收。

`pnpm runtime:dev` 根据依赖声明、锁文件、目标平台和安装规则复用原始 DSH 安装树。插件或代码补丁变化不再触发 `npm ci`。每份开发运行目录用同盘硬链接共享原始依赖文件，插件独立解包，补丁通过新文件原子替换，避免修改原始依赖或已运行版本。撤销补丁也从原始文件重新生成。开发目录必须放在支持硬链接的同一文件系统；不自动退回整树复制。目录大小统计会重复计算硬链接，不能直接相加当作磁盘占用。

生成目录由工具管理，不直接编辑其中的依赖；修改通过源码、插件或版本补丁进入。输入变化时另建运行目录，让已有开发后台继续使用原内容。准备完成不会自动重启后台；使用 `pnpm dev:stop` 明确停止后再运行 `pnpm dev`，或通过开发窗口重启切换。停止会中断开发任务。

`pnpm runtime:prepare` 在独立的临时安装树组装发行归档，裁剪只应用于该归档。开发和发行使用同一组装顺序。先显式执行预装插件自己的 `build`（存在时），再用 `npm pack --ignore-scripts` 打包；安装锁定的 DSH 后应用版本化代码补丁，再把插件包放到 `plugins/` 并装入启动补丁。发行最后执行裁剪与压缩。每个插件负责产出自足的编译资源，解开插件包不会自动安装其依赖。

准备命令通过服务库的小型构建工具执行，以操作系统文件锁串行化插件构建和归档写入；开发准备还与开发后台启停、旧目录回收共用操作锁。通过 `pnpm` 命令进入，不直接调用内部 Node 准备脚本。工具复用现有 Rust 编译缓存，不随发行包交付。

构建插件后才判断运行包缓存，插件包字节、代码补丁及应用脚本、启动补丁均参与输入指纹。新增预装插件需要明确加入构建清单和启动组合。最终程序不能依赖源仓库或 workspace 链接。单文件发行验证见 [验证约定](../scripts/README.md)。

每个预装插件的实际 `.tgz` 会先在临时目录解包检查，再参与缓存判断与组装。检查覆盖 DSH 兼容版本、宿主入口、声明的客户端入口及各配置补丁文件，并用独立 Node 进程导入宿主模块；关闭全局模块搜索及 `NODE_PATH`、`NODE_OPTIONS` 注入，避免开发环境补足遗漏。导入检查只覆盖模块加载，插件激活及浏览器行为由运行时验证覆盖。

当前预装插件要求运行产物自足，声明非空 `dependencies`、`optionalDependencies` 或 `peerDependencies` 会使检查失败，即使当前 DSH 安装树碰巧包含同名包。需要外部运行依赖时先实现明确的依赖部署和验证，再放开此约束。构建期 `devDependencies` 和客户端通过 DSH 模块系统共享的依赖沿用各自声明。

## 去重与精简取舍

| 当前选择 | 原因与保留边界 | 升级时重新判断 |
| --- | --- | --- |
| 将 Zod、debug、ms 的共享版本固定在运行时顶层 | 避免多个依赖重复嵌套同版本；保持上游声明的兼容范围，不使用强制 overrides 消除版本冲突 | 上游是否仍有重复；现有固定是否仍兼容；必要时调整或撤销额外固定，允许不兼容版本并存 |
| 排除 source map、PDB 等调试元数据 | 优先缩小发行体积，接受发行包中调试映射与符号信息减少；安装树仍保留 | 这些文件是否开始参与运行功能或新的调试交付需求 |
| 排除明确的异系统/异架构预编译文件 | 当前发行只需要目标平台代码；不能根据不认识的文件名猜测用途 | 上游平台命名和目录结构是否变化；目标架构与兼容后备实现是否被误排除 |
| 保留类型声明、TypeScript 源码、许可证及相关声明 | 兼顾插件开发、包的实际入口与分发义务，不用扩展名一刀切 | 新依赖的导出、加载方式和许可要求是否改变 |
| 用 File Viewer 替换 Word、PowerPoint 侧栏预览，移除所有平台的 LibreOffice Kit 运行内容及 WASM 后备引擎 | 以浏览器预览降低分发体积并扩展格式；禁用 `office-to-pdf` 并移除旧预览注册，保留许可证与声明。Office skill 未启用，后台 Office 转 PDF、渲染和重算不属于当前发行能力 | 新增消费者是否需要 LibreOffice，预览版式能否满足需求；恢复引擎时必须同步调整组合、补丁及验证 |
| 保留图片、语音、Web 及其他现有 WASM 内容 | 保留已选择的功能与非 Office 后备实现 | 功能依赖是否变化；不能仅凭某次未调用就认定不需要 |

精确文件规则以 [裁剪规则](../scripts/runtime-files.mjs) 为准。未知内容先保留；许可证优先于裁剪。依赖升级后重新审视规则，不把某一版安装布局固化为永久前提。

## 压缩选择

准备运行包统一使用 Node 内置的 Zstd 9。相比更高的压缩级别，接受略大的归档，以缩短重打包时间并保持各平台共用一条压缩路径。解压库内嵌，构建和运行均无需额外安装压缩工具。输入未变时直接复用已有归档。

调整格式或参数时，对同一份内容比较体积、构建成本、解压成本与额外工具要求。纯解压耗时不等于首次启动耗时，算法对比也不能代替真实 EXE 释放测试。测量属于有日期的证据，不作为永久体积或时延承诺；见 [首次压缩对比记录](records/2026-11-05-runtime-size.md)。

## 释放与复用

发行运行目录位于 Wingmate [管理目录](../crates/wingmate-service/README.md#数据与管理边界)下，统一命名为 `runtimes/dsh-<固定版本>-<SHA-256 前 6 位>`。指纹在构建时从实际内嵌的归档计算，目录通过 `.wingmate-revision` 中的完整指纹确认可复用。若同名路径被占用且无法确认指纹一致，启动会报错，可检查并手动移走占用路径后重试。

首次释放完成后才启用目标目录，避免中途退出使半成品被当作已有版本。运行文件损坏时，停止后台后手动删除对应指纹目录，再启动程序。

开发与发行均在后台身份、运行包指纹和 `running` 状态确认后，持启停操作锁回收旧运行目录。仅构建成功或连接到旧后台不触发新版回收，启动失败保留旧内容。开发还保留最近准备、尚未启动的目录，并按剩余目录引用回收原始依赖缓存；发行只保留当前受管运行包。清理仅针对各自运行根目录下符合指纹命名的普通目录，发行目录还需有与六位短名匹配的完整指纹标记。清理跳过链接与非托管内容，不涉及会话、设置或凭据。清理失败写入日志，下次成功启动或连接同版后台时重试仍能识别的目录。旧长指纹目录和仅按版本命名的旧发行目录可在后台停止后手动清理。

成功切换后不额外保留历史版本。回退需要重新准备开发内容，或用旧 EXE 重新释放其内嵌运行包。准备过程的临时目录在命令正常结束时清理，硬中断留下的临时目录不根据年龄或文件名直接推断为可删除。

同一 DSH 版本增加预装插件或修订随包内容时，已有后台继续使用原目录。用新版 Wingmate 明确重启后台，或在后台停止后用新版启动，才会释放并使用新指纹目录。更换 DSH 版本的处理见 [服务模块](../crates/wingmate-service/README.md)。

发行构建缓存同时核对构建输入和归档指纹，避免复用损坏或与输入不匹配的归档。释放目录用归档指纹识别随包内容，启动时直接复用同指纹目录。npm 获取依赖仍按锁文件校验完整性。

## 升级时需要作出的判断

| 环节 | 需要确认并留下的结论 |
| --- | --- |
| 选择版本 | 获取来源及具体版本；上游变更是否改变 Node 前提、配置/数据兼容性、插件机制或默认行为 |
| 更新依赖 | 锁文件变化是否符合本次升级范围；额外顶层固定还有没有必要；有无新增原生库、下载步骤或系统依赖 |
| 调整适配 | 现有补丁和裁剪是否仍适用；上游已解决的问题是否可以撤销本地适配；是否引入行为差异 |
| 准备发行 | 是否仍能从受管理的输入准备单文件产物；新内容如何影响首次释放及已有版本目录 |
| 验证与交付 | 哪些能力受影响、做了哪些验证、还有哪些未验证；旧后台和既有数据如何继续使用或切换 |

验证入口在 [根 README](../README.md#开发入口)。DSH 升级、发行内容或裁剪变更需要覆盖实际单文件释放、Web 连接、后台管理及受影响的原生组件；仅压缩参数变化也需检查解压内容一致和真实启动。

涉及插件加载、安装或配置变更，补充对应插件验证；涉及 Node 前提、系统或架构变化，针对目标环境验证。涉及数据格式变化，先使用隔离副本验证兼容性，不拿日常会话作为试验数据。

记录能力边界：语音库加载不等于模型推理通过，Web 打开不等于真实模型调用通过，Office 转换用例通过也不代表所有格式都已覆盖。具体验证原则见 [验证约定](../scripts/README.md)。

## 社区和自用插件集成

当前预装 [Wingmate 后台服务](../plugins/wingmate-web/README.md)和[文件预览](../plugins/wingmate-file-viewer/README.md)。构建脚本明确指定预装哪些包，[启动补丁](../plugins/cordis.patch.yml)决定 Wingmate 启动 Web 时默认启用哪些插件。开发版和发行版均随运行包携带这份补丁，并将它计入构建指纹。参考仓库、本地开发插件、发行预装组件是不同状态，创建目录或加入开发 workspace 不会自动改变发行内容。

第一次实际集成时建立简短记录：本项目维护的插件写在所属 `plugins/<名称>/README.md`；仅消费外部发布包的组件写在 `docs/integrations/<名称>.md`。后者目录在实际需要时创建。记录包含：

| 内容 | 要说明的问题 |
| --- | --- |
| 目的与来源 | 为什么集成、提供什么能力、上游地址；精确版本以哪个声明/锁文件为准 |
| 许可与发行 | 是否允许所选分发方式，需要保留什么声明；是否随包提供及是否默认启用 |
| 兼容与依赖 | 适配的 DSH 范围、Node/原生/系统依赖，有无额外下载和用户配置要求 |
| 客户端能力 | Web、TUI、移动端分别是已验证、未验证还是不支持；后端加载不能替代界面验证 |
| 本地适配 | 是否改动上游，改动原因、对应问题/提交、升级检查点和撤销条件 |
| 验收与退出 | 验证哪些用户可见能力；移除或禁用后配置、数据和已有工作流会怎样 |

预装和默认启用要分别决定；不携带个人凭据，不无记录地覆盖用户已有配置。开发目录中的插件要先形成可安装产物，再接入发行依赖，不依赖工作区链接。

预装插件与 DSH 共同纳入运行包指纹，并随运行包切换。

## 适配与升级记录

代码补丁保存在 `runtime/patches/dsh-<版本>.json`，按数组顺序应用到从原始依赖准备的新运行目录。每项记录包版本、目标文件、原始 SHA-256、唯一匹配的替换内容及对应源码链接。版本、文件哈希或匹配次数不符时构建失败；升级 DSH 时需审查并提供对应版本清单，无补丁时显式使用空数组。补丁不直接修改已有运行目录，也不依赖本机 Git 命令。

配置组合优先使用 DSH 的 patch 和插件接口；代码补丁用于上游尚无扩展点的必要改动，原因和撤销条件放在对应插件文档。以后需要源码构建时，先从受管理的 URL、tag 与 commit 准备干净源码并应用补丁，再把编译包接入运行时组装，不能只修改 `stage` 或被忽略的参考仓库。

实际 DSH 升级、预装组件变化或兼容性调整时，在 `docs/records/` 新增有日期的简短记录：变更目标与前后版本、输入/来源、此次取舍及适配变化、验证环境和结论、已有安装的处理方式、未验证项。只记录发生的工作，不预建空台账。

当前约定更新在本指南或所属模块；历史记录保留当时结论，不持续改写成最新状态。已有记录包括 [2026-11-05 运行时体积优化](records/2026-11-05-runtime-size.md)、[2026-11-08 Wingmate 后台服务插件](records/2026-11-08-wingmate-web.md)、[2026-11-10 文件预览与 LibreOffice 裁剪](records/2026-11-10-file-viewer.md)和[开发依赖复用与运行目录回收](records/2026-11-10-runtime-reuse.md)。
