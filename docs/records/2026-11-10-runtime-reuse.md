# 2026-11-10 开发依赖复用与运行目录回收

本次调整开发准备和运行目录生命周期，DSH 版本、插件内容与 Zstd 9 保持既有选择。长期规则见[运行时维护指南](../runtime-maintenance.md)。

## 实现取舍

- 将生成内容迁入 `work`，保留原 `target` 编译缓存。开发依赖按锁文件、平台、Node ABI 与安装规则复用；插件和补丁变化只生成新的运行目录。
- 为保留旧后台及启动失败时的旧内容，运行目录采用同盘硬链接共享依赖，而非直接覆盖唯一安装树。补丁通过原子替换断开目标文件的硬链接，原始包和旧运行目录不受影响。
- 构建工具复用服务库的操作系统文件锁。开发准备与后台启停、回收互斥，开发和发行插件构建也串行化。新增 `pnpm dev:stop`，避免凭 `target/debug` 路径推断后台归属。
- 新版身份、指纹及 DSH 就绪状态确认后才回收旧内容，开发额外保护最近准备但尚未启动的版本。清理失败记录日志并重试，不使已成功的启动失败。

## 验证

Windows x64、Node 24.15.0、本地 NTFS 环境。

- 自动化测试覆盖共享文件的补丁隔离、重做与撤销，以及当前目录、待启动目录和非托管内容的保留；失败或不同指纹的后台不触发清理。
- 在旧开发后台运行期间准备下一版，未重新执行 `npm ci`。原始依赖与两个运行目录中抽查的 DSH 入口拥有相同文件标识，硬链接数为 3；旧后台实例保持不变。
- 切换后旧运行目录被删除。依赖缓存指纹变化时准备新缓存，使用损坏 YAML 制造真实启动失败，旧运行目录和缓存仍保留；修复后启动成功，两者自动回收。
- 旧 `runtime/stage` 已随新开发后台成功启动回收，归档与 npm 缓存迁移完成。最终开发环境只保留一份运行目录和一份原始依赖缓存。测试开发后台已停止，日常发行后台未被重启。
- `pnpm build` 成功；再次准备发行归档命中缓存。归档 SHA-256 仍为 `1e21e316d801efe1b1615d623f7805bbfd8ad82b6e8e6677ac98a1d92f68e9be`，浏览器资源与上次验收一致。
- 最终 `pnpm test`、带发行 feature 的服务库测试和 `pnpm test:smoke` 均通过。单文件冒烟验证真实 EXE 启动后回收旧指纹目录、保留非托管目录，以及原有认证、后台生命周期、静态资源和原生模块检查；本地报告在 `work/smoke-KdqpOY/result.json`。
- 收尾将冒烟目录移至 `work/tests/smoke-*`，默认在确认停止后删除副本，成功仅留报告，失败保留日志；显式保留与停止失败路径也已验证。此前的重型测试副本已清理。
- 提交前审核复现了冒烟误接收非隔离 EXE 的问题，已增加首次启动前的管理目录检查，并用实际开发 EXE 验证不会启动开发后台。新增原生 CLI 测试夹具覆盖隔离、失败清理、停止失败、显式保留和拒绝已有目录；同时修正补丁原子替换时可能受 Unix `umask` 影响的权限变化，在共享依赖测试中加入权限保留断言。

本地生命周期证据在 `work/runtime-lifecycle-check/`。就绪判断沿用 DSH 的后台状态，不代表所有可选插件的业务功能均已验收；测试发现缺失的可选插件可能只记录错误而不阻止 DSH 就绪，因此失败场景采用无法解析的启动配置。macOS、Linux、Android 未运行验收；开发硬链接要求同一支持该能力的文件系统，发行释放不依赖硬链接。
