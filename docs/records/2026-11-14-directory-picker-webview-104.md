# 2026-11-14 WebView 104 工作台浮窗

在 Redmi Note 10 Pro 的 Android System WebView 104.0.5112.97 上，用 DSH 0.2.2-rc.1 复现「添加工作区」浮窗内目录不可见。真实 WebView 的 CDP 显示目录节点已加载，列表实际高度为 0，`CSS.supports` 确认浏览器拒绝使用 `dvh` 的高度声明。添加 `vh` 回退后，390 × 873 CSS 像素视口内浮窗高度为 500 像素，目录列表高度为 271 像素。

使用独立包名的 Android 本地 Debug 版覆盖安装，通过原有载荷更新机制启动，验证目录可选并可添加为工作区。远程 Debug 版通过 USB 转发连接 Windows 的 Wingmate 开发网关，验证同一个浮窗的目录可见且可取消。Edge 157 在 450 像素高的视口中仍采用 `dvh` 声明，浮窗高度为 418 像素。Android 本地和远程 Debug 构建、相关 Node 与 Gradle 单元测试均通过。远程验证使用 USB 转发，未完成 Wi-Fi 直连验收。

已有本地版通过 APK 携带的载荷更新获得修复。远程版由连接的 Wingmate 主机提供页面，需在主机更新运行时。

随后核对了 DSH 发布包内其他视口单位的用法。WebView 104 的计算样式显示，混用 `dvh` 与 `var()` 的声明即使写在 `vh` 回退之后，也会使通用工作区菜单的最大高度变为 `none`。自动化任务的时区菜单从 6184 像素高恢复到 420 像素，列表可在菜单内部滚动。真机还复验了目录列表、快捷键窗口的高度上限和网关配对页居中，并通过单独的样式探针验证了任务确认窗口的高度上限和右侧栏浮动面板的高度与位置。Edge 157 在 458 像素高的视口内将时区菜单限制为 410 像素，列表仍可滚动。
