# wingmate-service

负责本机 DSH 后台的所有权和生命周期，供桌面与管理入口共用。桌面 EXE 在启动时把运行锁交给 DSH 所在的 Node，控制接口也运行在该 Node 进程中。关闭窗口后仍可重新连接或替换桌面 EXE。跨模块使用预期见 [项目约定](../../docs/product.md)。

## 服务管理边界

- 发现并复用的对象必须是可确认身份的本项目后台，不能仅凭端口、进程名或陈旧发现文件接管其他进程。
- 只有确认归属的 DSH 进程才在管理范围内。显式停止通过 DSH 的关闭钩子完成清理。Windows 上由 Node 持有 Job Object，进程退出时系统回收受管子进程。
- 当前管理接口只服务于同一用户的本机使用，不作为远程认证或系统服务方案。
- 发现不同 DSH 版本时，不自动升级或重启已有后台。先用原版本停止，再使用新版启动，避免无意中中断工作。

## 数据与管理边界

默认管理目录为 `~/.wingmate`；`WINGMATE_HOME` 可指定另一个绝对路径。这里保存后台管理状态、日志及可重新释放的运行内容，不接管 DSH 的会话、凭据和设置。

管理凭据和 Web 访问 token 不在普通 CLI 状态中展示。测试数据必须与日常数据隔离，发现文件仍属于同用户本机信任边界。

运行内容按版本复用的约定与人工刷新方式统一见 [释放与复用](../../docs/runtime-maintenance.md#释放与复用)；服务模块不另设哈希校验或自动覆盖策略。

本机管理控制入口随 EXE 更新，从已有 DSH 版本目录独立加载。这样仅修改管理协议或启动逻辑时，可以继续复用已释放的 DSH 内容。
