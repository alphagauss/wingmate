# 构建与验证约定

本目录承载仓库级准备、打包与验证。命令入口见 [根 README](../README.md#开发入口)，运行内容的选择与升级验收见 [运行时维护指南](../docs/runtime-maintenance.md)。

构建目录和应用占用的处理见[本地开发与构建](../docs/runtime-debugging.md#本地开发与构建)。

## 验证边界

- 日常开发和功能验证使用 `pnpm dev` 与相关自动化测试。开发运行时的准备和复用见[本地开发与构建](../docs/runtime-debugging.md#本地开发与构建)。
- 需要运行验证时，只在当前开发机的操作系统上运行。其他操作系统只做受影响分支的静态检查，包括条件编译、平台 API 与依赖。验证记录应区分实际运行的平台和仅做静态检查的平台。
- 只有排查明确的发行版特有问题，或任务明确要求验收发行产物时，才验证实际发行版。正式发版、DSH 升级和涉及打包、释放、裁剪的改动属于发行产物验收。先用 `pnpm test:smoke` 在对应平台和架构检查单文件可执行程序和运行目录复用。发行验证使用测试专用目录，自动冒烟使用无个人凭据的数据。
- 冒烟副本默认创建于 `work/tests/smoke-*`，脚本会检查被测程序是否为使用隔离管理目录的发行模式。结束时停止并确认测试业务与管理服务均退出，成功仅保留 `result.json`。失败时还会保留已有的 `service.log` 和 `host.log`（存在时），报告记录失败原因。可执行文件、释放目录和测试数据默认清理，无法确认停止或清理失败时保留剩余内容并以失败退出。排查时用 `pnpm test:smoke --keep-work` 显式保留现场。脚本的可选目录参数必须指向尚不存在的新目录。强制终止脚本可能留下需要手动检查的现场。
- 记录冒烟或手动验证的结论后，按[收尾步骤](../docs/runtime-debugging.md#收尾)删除测试专用目录和剩余报告。
- 发行验收在最终释放内容上验证受影响的功能，包括涉及的终端、图片、Office 等原生能力。原生对话框外观、窗口焦点等需要现场观察的行为优先人工验证。
- 局域网网关的发行冒烟用回环地址验证真实工作台、文件和长连接、设备撤销及停机恢复。两套隔离服务可用于桌面双端回归。另一设备的网络可达性和扫码另用实际局域网验证。
- 语音库加载与模型推理、Web 认证与真实模型调用分别报告。缺少模型或凭据时记录未覆盖范围，不把它们计为功能验证通过。
- 运行依赖和裁剪变化验证功能保留；压缩比较使用相同内容，区分压缩、纯解压、落盘与完整启动成本。

测量值和验证结论属于具体版本、平台及环境。需要长期保留的结论写入有日期的 [发行记录](../docs/runtime-maintenance.md#适配与升级记录)，不在本文件维护不断过期的测试数量或耗时表。
